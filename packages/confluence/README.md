# @atlcli/confluence

Confluence REST client, bidirectional storage ↔ markdown conversion, and the
`ExportBlock` document model shared by the DOCX and PDF export engines.

- **Entry points:**
  - `.` / `./node` — the v1 surface: `ConfluenceClient`, `storageToMarkdown` /
    `markdownToStorage`, `storageToBlocks` + `ExportBlock`, mention
    resolution, page properties. Identical to `./browser`; statically clean
    of `node:`/`bun:` builtins.
  - `./browser` — same isomorphic surface for bundlers.
  - `./internal` — **non-frozen, Bun-only** repo machinery (sync-db on
    `bun:sqlite`, atlcli-dir, webhook server, poller, …). May change without
    notice.
- **Runtime:** Node ≥ 20, Bun, and browsers for `.`/`./browser`; Bun only for
  `./internal`.
- **Install:** filesystem link or packed tarball — no registry publish today.
  See the [package consumption guide](https://atlcli.sh/reference/package-consumption/).

```ts
import {
  collectAdfMediaFileIds,
  storageToBlocks,
  validateAdf,
} from "@atlcli/confluence";

const { blocks, notes } = storageToBlocks(page.storage);
const mediaFileIds = collectAdfMediaFileIds(validateAdf(pageAdf));
```

`collectAdfMediaFileIds()` is shared by Node and browser consumers. It walks
only bounded, validated ADF and returns stable, deduplicated Media Services
`fileId` values. `ConfluenceClient.getExportPageDetailsWithMedia()` uses this
contract to stop attachment cursor pagination once every referenced ID has
been resolved; unresolved IDs remain explicit and continue through the
export-note degradation path.

## Delivering generated files as page attachments

`createPageAttachmentWriterV1()` is the browser-safe delivery seam for
generated DOCX/PDF artifacts. It accepts a host request function instead of
owning authentication:

- CLI/token callers may keep using `ConfluenceClient`.
- Extension/session and normal-browser callers inject their allowed
  same-origin request.
- Forge Custom UI passes an adapter around `requestConfluence`; this package
  never imports `@forge/bridge`.

The writer performs an exact-name Cloud v2 preflight before create, sends
multipart v1 create/update requests, and never retries a non-idempotent POST.
Create conflicts remain explicit and never silently overwrite an attachment.

### CLI/token transport

The existing client signatures remain compatible. `Uint8Array` inputs are
adapted to the common writer internally on Confluence Cloud:

```ts
import { ConfluenceClient } from "@atlcli/confluence";

const client = new ConfluenceClient(profile);
const created = await client.uploadAttachment({
  pageId: "123",
  filename: "handbook.pdf",
  data: pdfBytes,
  mimeType: "application/pdf",
  comment: "Generated by the release pipeline",
});

await client.updateAttachment({
  pageId: "123",
  attachmentId: created.id,
  filename: "handbook.pdf",
  data: revisedPdfBytes,
  mimeType: "application/pdf",
});
```

### Session fetch in an extension or same-origin browser host

The common writer introduces neither `Authorization` nor `credentials`.
The host owns both. A Confluence-session host can explicitly keep ambient
cookies under its own same-origin policy:

```ts
import {
  createPageAttachmentWriterV1,
  type ConfluenceProductRequestV1,
} from "@atlcli/confluence/browser";

const siteOrigin = "https://example.atlassian.net";
const sessionRequest: ConfluenceProductRequestV1 = (path, init) =>
  fetch(new URL(path, siteOrigin), {
    ...init,
    credentials: "include",
    redirect: "manual",
  });

const writer = createPageAttachmentWriterV1(sessionRequest);
const existing = await writer.findByFilename({
  pageId: "123",
  filename: "handbook.pdf",
});

if (existing) {
  await writer.updateData({
    pageId: "123",
    attachmentId: existing.id,
    filename: "handbook.pdf",
    body: pdfBlob,
    mimeType: "application/pdf",
  });
} else {
  // create() repeats the bounded preflight so the caller's earlier check
  // cannot turn a concurrent same-name create into an accidental overwrite.
  await writer.create({
    pageId: "123",
    filename: "handbook.pdf",
    body: pdfBlob,
    mimeType: "application/pdf",
  });
}
```

A normal webpage receives no CORS or same-origin bypass from atlcli. Its
injected request must already be permitted to call the Confluence product
paths. `Blob` inputs stay Blob-backed through `FormData`; atlcli never calls
`arrayBuffer()` on them.

### Forge Custom UI transport

Only the consuming Forge app imports the bridge:

```ts
import { requestConfluence } from "@forge/bridge";
import { createPageAttachmentWriterV1 } from "@atlcli/confluence/browser";

const writer = createPageAttachmentWriterV1((path, init) =>
  requestConfluence(path, init),
);

await writer.create({
  pageId: "123",
  filename: "handbook.docx",
  body: docxBlob,
  mimeType:
    "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
  comment: "Generated from the current page",
});
```

The common contract deliberately does not promise cancellation: hosts differ,
and Forge Bridge does not preserve `AbortSignal` today. Forge also serializes
multipart files across the bridge, which adds consumer-side memory overhead
that Blob-first handling inside atlcli cannot remove.

### Typed failures and safe retry decisions

Failures reject with `AttachmentDeliveryError`. Its stable `kind` is one of
`forbidden`, `not-found`, `name-conflict`, `rate-limited`, `too-large`,
`invalid-response`, or `transport`. The error also exposes the operation,
HTTP status when known, and two decision fields:

- `requestMayHaveSucceeded` is true when a create/update outcome is ambiguous.
- `requerySuggested` tells the host to resolve current attachment state before
  choosing a retry.

The error never retains file bytes, multipart bodies, or authentication data.
