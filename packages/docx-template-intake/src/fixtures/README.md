# Neutral DOCX intake fixtures

These fixtures are synthetic and brand-neutral. They exist to characterize
DOCX producers and to calibrate resource limits before the intake engine is
implemented. They contain no customer, tenant, account, or copied document
data.

## Binary fixtures

| Fixture | Source and generator | Expected OOXML features | SHA-256 |
|---|---|---|---|
| `neutral-generated-python-docx-1.2.0.docx` | Generated from `tools/create-neutral-source.py` with Python 3.14.2, python-docx 1.2.0, and Pillow 12.2.0 | Named paragraph styles and inheritance, theme colors and fonts, direct formatting, table styling, portrait and landscape sections, first/default/even headers, footer, page border, document background, PNG, JPEG, and SVG with a raster fallback | `246e3c3e0a1d8db6ab6049dc750c64620fbc40dab7e740da6b92d3d303cdb8fa` |
| `neutral-word-16.111.1.docx` | The generated fixture opened and saved as a current Word document by Microsoft Word for Mac 16.111.1, then privacy-scrubbed | The same semantic styles, theme, sections, producer-normalized headers/footers, border/background, raster visuals, and SVG with raster fallback after Word normalization | `938e7a9d105a41ffa14baedf37f21f4388cc1b2131be7e16ad73f5b5a4a8cf4a` |
| `neutral-libreoffice-7.1.1.2.docx` | The generated fixture opened and saved as Office Open XML by LibreOffice 7.1.1.2 | The same semantic styles, theme, sections, border/background, and raster visuals after LibreOffice normalization; LibreOffice omits the SVG extension and normalizes header/footer part topology | `688e49f1cb7d0acb31a3c5c4398fbcba14675c6785a0d1e9a75114fabdcdd466` |

## Reproduction

Run the generator with the bundled document runtime, then perform the two
producer saves without editing document content:

```bash
python3 tools/create-neutral-source.py \
  --output neutral-generated-python-docx-1.2.0.docx
```

1. Open the generated DOCX in Word 16.111.1.
2. Choose **Save As**, clear compatibility mode, and save it as
   `neutral-word-16.111.1.docx`.
3. Run the document-runtime `privacy_scrub.py` over the Word result so local
   author metadata and revision IDs cannot enter the repository.
4. Open the generated DOCX in LibreOffice 7.1.1.2 and save it in Office Open
   XML format as `neutral-libreoffice-7.1.1.2.docx`.
5. Run `bun --conditions=development
   src/fixtures/tools/update-goldens.ts` from this package directory.
6. Recompute SHA-256 values, update this table, render every page, and inspect
   each rendered page before accepting a fixture change.

The producer-specific binaries are intentionally not byte-identical. Their
text-free analysis goldens describe their structure without copying document
content.

## Permitted synthetic text

The privacy test permits only these deliberately synthetic document markers:

- `NEUTRAL_FIXTURE_TITLE`
- `NEUTRAL_FIXTURE_SUBTITLE`
- `NEUTRAL_HEADING_ONE`
- `NEUTRAL_HEADING_TWO`
- `NEUTRAL_HEADING_THREE`
- `NEUTRAL_BODY_ALPHA`
- `NEUTRAL_BODY_BETA`
- `NEUTRAL_CODE_SAMPLE`
- `NEUTRAL_CAPTION`
- `NEUTRAL_TABLE_HEADER_A`
- `NEUTRAL_TABLE_HEADER_B`
- `NEUTRAL_TABLE_CELL_A`
- `NEUTRAL_TABLE_CELL_B`
- `NEUTRAL_HEADER_DEFAULT`
- `NEUTRAL_HEADER_FIRST`
- `NEUTRAL_HEADER_EVEN`
- `NEUTRAL_FOOTER`
- `NEUTRAL_SECTION_TWO`

The only permitted synthetic metadata values are:

- `ATLCLI Synthetic Fixture`
- `Neutral DOCX Template Fixture`
- `ATLCLI_SYNTHETIC_FIXTURE`
- `generated by python-docx`

Standard OOXML namespace and schema URLs are allowed as format identifiers.
No other URL is permitted in a fixture or golden.
