## Dependency notes

- Plan 001 is intentionally atomic: Astro 7 and Starlight 0.41 do not share a
  supported peer-dependency range with the currently installed versions, so
  intermediate dependency commits would leave the documentation site broken.

## Findings considered and rejected

- Staged Astro 5 → 6 → 7 installations: unnecessary. The migration guides must
  both be reviewed, but the repository can resolve the final compatible set in
  one lockfile update.
- Adding a unified/remark Markdown processor preemptively: not justified. The
  site has no remark, rehype, or recma plugins, and Starlight 0.41 supports
  Astro 7's Sätteri pipeline.
- Adding Mermaid or a blog during the upgrade: out of scope. These appear only
  in historical migration plans and are not part of the live site.
- Refactoring the manual sidebar to autogenerated groups: unrelated to the
  framework upgrade and would make route/order regressions harder to isolate.
- Changing the shared `dist/` output directory: useful follow-up work, but not
  required for Astro 7. CI jobs are clean and isolated; changing output paths in
  this migration would add deployment risk without improving compatibility.
