# Plan 008: Render Word equations deterministically without tenant-specific macros

Status: **Planned**

Planned at: `18f6f1e`, 2026-07-20

Priority: **P2** · Effort: **L** · Risk: **HIGH**

Depends on: completed `specs/import-docx-mvp/PLAN.md`

> **Executor instructions:** Mathematical meaning is more important than visual similarity. Preserve source OMML provenance, accessible text, and a deterministic fallback. Never emit raw OMML, active SVG, arbitrary LaTeX macros, or a Marketplace equation macro without a proven typed capability. Record dependency/version/license/bundle evidence, math corpus results, output digests, Cloud IDs, and cleanup in `specs/import-docx/008-equations/EVIDENCE.md`.

---

## 1. Outcome and JTBD

Word equations receive a deterministic, locally generated, safe, accessible representation that works in both Cloud ADF and Data Center Storage. Supported expressions render as a sanitized image plus linear/accessible text; unsupported expressions retain readable fallback and a precise issue. The result is isomorphic and reproducible across Bun, Node, and the neutral browser harness.

JTBD: **migrate scientific, engineering, medical, or contractual formulae without replacing meaning with an empty placeholder or requiring a tenant-specific app**.

Research basis:

- Canary's February 2026 changelog advertises embedded formula support, demonstrating market demand but not its internal fidelity approach: https://canaryapps.atlassian.net/wiki/spaces/DOCX/pages/324763650/Documentation
- Canary Marketplace listing: https://marketplace.atlassian.com/apps/3691041528/word-importer-for-confluence
- The current MVP intentionally supports package previews/readable fallback and defers native equation mapping; this plan promotes deterministic rendering without weakening that fallback.

No strong Confluence-specific public JTBD volume was found for equations. This is a breadth/fidelity investment justified by technical-document use cases and competitive capability, so it remains P2.

---

## 2. Scope

In scope:

- validated extraction of OMML equation islands and package-provided previews;
- neutral math model or validated MathML intermediate hidden behind an adapter;
- deterministic local SVG/PNG rendering with safe alt/linear text;
- inline and display equations, common operators, fractions, scripts, roots, matrices, delimiters, accents, n-ary operators, functions, and equation arrays;
- exact dependency pins, browser bundle/runtime/security evidence;
- target attachment/media encoding and semantic readback;
- Cloud live and DC contract proof.

Out of scope:

- executing Word/Office automation;
- arbitrary TeX macro packages or remote font fetches;
- tenant Marketplace macros;
- equation editing UI in Confluence;
- guaranteeing Word layout/font/pagination parity;
- OCR of equations in images/PDF.

## 3. Architecture and fallback ladder

```text
validated OMML island
  -> OmmlAdapter
  -> MathExpression { semantic source digest, accessible linear text, render tree }
  -> DeterministicMathRenderer port
  -> sanitized SVG or deterministic PNG + dimensions + digest
  -> normal MVP ImportAsset/media pipeline
```

```ts
export interface MathExpression {
  id: string;
  display: "inline" | "block";
  sourceOmmlDigest: string;
  accessibleText: string;
  renderTree: MathNode;
  unsupportedFeatures: string[];
}

export type MathRenderOutcome =
  | {
      mode: "rendered";
      mediaType: "image/svg+xml" | "image/png";
      bytes: Uint8Array;
      width: number;
      height: number;
      sha256: string;
      alt: string;
    }
  | { mode: "package-preview"; assetId: string; alt: string }
  | { mode: "text-fallback"; text: string; issueCode: string };
```

Fallback order:

1. validated supported OMML → deterministic renderer;
2. safe package-provided preview whose relationship/digest/dimensions are proven;
3. accessible linear text plus `equation-rendering-unsupported`;
4. `--strict` blocks on approximation when required by policy.

Invariants:

- Raw XML/parser types do not enter public IR or target encoders.
- Rendering is pure over validated data and local frozen assets; no filesystem/network/DOM globals in the browser entrypoint.
- SVG is generated by trusted renderer code, sanitized/structurally validated, contains no script/event/external URL/font/style imports, and passes baseline preview/asset security checks. If safe SVG cannot be guaranteed, use deterministic PNG.
- Font files are exact, redistributable, locally bundled, size-accounted, and license-recorded. Platform fonts are forbidden because they break reproducibility.
- Semantic digest uses source expression/accessible text plus expected target outcome, not generated attachment IDs/URLs.
- Equation images carry non-empty alt text; display equations also have a readable adjacent fallback when target accessibility requires it.

## 4. Dependency decision gate

Task 0 must compare maintained OSS JS/TS-capable OMML/MathML/rendering options and the cost of a focused in-house OMML subset. For every proposed dependency record exact version, repository commit/tag, license, maintainers/releases, install scripts/native binaries, transitives/licenses, unpacked/browser bundle size, CSP/Worker compatibility, font assets, vulnerabilities, and deterministic output.

Selection constraints:

- exact manifest versions and frozen lockfile;
- permissive license compatible with Apache-2.0 distribution;
- no Word/LibreOffice binary, native addon, remote service, runtime network, or browser DOM requirement;
- adapter-hidden types and replaceable renderer;
- byte-stable output or canonicalization proven across supported runtimes.

If no candidate meets this bar, implement only the validated OMML-to-accessible-text subset and retain package previews; do not introduce a risky renderer to match a competitor checkbox.

## 5. CLI and reporting

```text
--equations <mode>  auto|render|preview|text|fail (default auto)
```

- `auto`: deterministic render, then package preview, then text fallback with warning.
- `render`: require supported deterministic rendering.
- `preview`: require safe embedded preview.
- `text`: accessible text only, explicitly reported.
- `fail`: any source equation blocks before publication.

Preview shows source count, rendered/preview/text/failed count, unsupported OMML feature codes, alt text, and safe thumbnail subject to output budgets.
