# PDF import quality neutral corpus

Every source and PDF in this directory was authored specifically for AtlCLI
under the repository's Apache-2.0 license. Customer documents, excerpts,
screenshots, metadata, hashes, and tenant data are prohibited.

The corpus has two reproduction classes:

- `independent-*.pdf` is generated byte-identically by `generate-core.ts` with
  Bun. It contains the small, exact positive and negative PDF structures used
  by automated quality gates.
- `producer-*.pdf` is a pinned neutral export from Word, LibreOffice, or
  Chromium. Desktop producer output is not byte-deterministic, so CI consumes
  the reviewed bytes and verifies their provenance and digests.

`manifest.json` binds every PDF to its SHA-256, byte length, producer
provenance, exact ordered blocks, boundary actions with source-character
indexes, structure outcomes, ownership/fallback expectations, and safe links.
The expected semantics are authored independently of the importer.

## Regenerate the independent core

```bash
bun specs/pdf-import-quality/fixtures/generate-core.ts
bun specs/pdf-import-quality/fixtures/update-manifest.ts
bun run test packages/import-pdf/src/fixtures.test.ts
```

The test generates the core twice and compares both runs byte-for-byte with
the committed PDFs. It also proves the required PDFium facts and scans source,
binary, and extracted evidence for prohibited private terms.

## Prepare a neutral desktop producer source

Desktop export is an explicit review operation and is not part of CI. Create a
temporary environment with the exact pins in `producer-requirements.txt`, then
prepare the DOCX outside the repository:

```bash
python3 -m venv .tmp/pdf-import-quality-producer-venv
.tmp/pdf-import-quality-producer-venv/bin/pip install \
  -r specs/pdf-import-quality/fixtures/producer-requirements.txt
.tmp/pdf-import-quality-producer-venv/bin/python \
  specs/pdf-import-quality/fixtures/producer-tools.py producer-source \
  --output .tmp/pdf-import-quality-producer.docx
```

Export that neutral DOCX with Word and LibreOffice. Export
`producer-source.html` with Chromium. Sanitize each raw export before it enters
the corpus:

```bash
.tmp/pdf-import-quality-producer-venv/bin/python \
  specs/pdf-import-quality/fixtures/producer-tools.py sanitize-export \
  --input .tmp/raw.pdf \
  --output specs/pdf-import-quality/fixtures/producer-example.pdf \
  --producer "Neutral producer and exact version"
```

Sanitization replaces document metadata, removes timestamps and XMP metadata,
and prunes unreferenced cloned objects. It does not make a private input safe.
Never run a private PDF through this tool.

After updating a pinned producer export, update `manifest.json`, render every
page, inspect it visually, run `pdfinfo`, and run the fixture test. The pinned
LibreOffice fixture intentionally records its observed CJK variance: the
Japanese text is present in the text layer but the local exporter did not
materialize a visible glyph. It is a critical negative, not positive visual
CJK evidence; the independent, Word, and Chromium fixtures provide positive
CJK coverage.
