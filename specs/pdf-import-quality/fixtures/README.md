# PDF import quality neutral corpus

Every source and PDF in this directory was authored specifically for AtlCLI
under the repository's Apache-2.0 license. Customer documents, excerpts,
screenshots, metadata, hashes, and tenant data are prohibited.

The corpus has two reproduction classes:

- `independent-*.pdf` is generated byte-identically by `generate-core.ts` with
  Bun. It contains the small, exact positive and negative PDF structures used
  by automated quality gates.
- `producer-*.pdf` is a pinned neutral export from Word, LibreOffice, or
  Chromium. Desktop producer output is not byte-deterministic, so CI consumes
  the reviewed bytes and verifies their provenance and digests.

`manifest.json` binds every PDF to its SHA-256, byte length, producer
provenance, exact ordered blocks, boundary actions with source-character
indexes, structure outcomes, ownership/fallback expectations, and safe links.
The expected semantics are authored independently of the importer.

## Run the semantic quality gate

```bash
bun run check:import-pdf-quality
bun run test scripts/quality/import-pdf-quality.test.ts
```

The first command evaluates every fixture and producer family independently.
Its JSON output contains only fixture IDs, counts, rates, and gate codes—never
expected or extracted body text. The focused test also perturbs one expected
block and one expected boundary to prove that the owning fixture fails instead
of being hidden by an aggregate.

## Regenerate the independent core

```bash
bun specs/pdf-import-quality/fixtures/generate-core.ts
bun specs/pdf-import-quality/fixtures/update-manifest.ts
bun run test packages/import-pdf/src/fixtures.test.ts
```

The test generates the core twice and compares both runs byte-for-byte with
the committed PDFs. It also proves the required PDFium facts and scans source,
binary, and extracted evidence for prohibited private terms.

## Prepare a neutral desktop producer source

Desktop export is an explicit review operation and is not part of CI. Prepare
the neutral DOCX outside the repository (no extra dependencies; Bun only):

```bash
bun specs/pdf-import-quality/fixtures/producer-tools.ts producer-source \
  --output .tmp/pdf-import-quality-producer.docx
```

Export that neutral DOCX with Word and LibreOffice. Export
`producer-source.html` with Chromium. Sanitize each raw export before it enters
the corpus:

```bash
bun specs/pdf-import-quality/fixtures/producer-tools.ts sanitize-export \
  --input .tmp/raw.pdf \
  --output specs/pdf-import-quality/fixtures/producer-example.pdf \
  --producer "Neutral producer and exact version"
```

Sanitization rewrites the PDF from its trailer: it keeps object numbers and
stream bytes, replaces the Info dictionary with neutral values, removes XMP
metadata and timestamps, and drops every object the document does not
reference. `producer-tools.test.ts` proves that PDFium facts are unchanged. It does not make a private input safe.
Never run a private PDF through this tool.

After updating a pinned producer export, update `manifest.json`, render every
page, inspect it visually, run `pdfinfo`, and run the fixture test. The pinned
LibreOffice fixture intentionally records its observed CJK variance: the
Japanese text is present in the text layer but the local exporter did not
materialize a visible glyph. It is a critical negative, not positive visual
CJK evidence; the independent, Word, and Chromium fixtures provide positive
CJK coverage.

## Acceptance fixtures (PIQ-18)

`acceptance-browser.pdf` and `acceptance-libreoffice.pdf` export one neutral
document: a heading, a paragraph and a list, a 61-row tagged table continued
across pages with a repeated header, an intentionally blank header cell and
body cell, wrapped punctuation-bearing cells, a decorative rule, one raster
figure with caption followed by body text, and a second table.

`acceptance-source.ts` is the single content model. It writes
`acceptance-source.html` and provides the oracle: the ordered blocks, the table
shapes (`tables`) and the figure counts (`figures`). Only page indexes come
from the export, located in the PDFium text layer by `acceptanceBlockPages()`
because pagination is the producer's choice. Nothing in the oracle is taken
from importer output.

```bash
bun specs/pdf-import-quality/fixtures/acceptance-source.ts
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --no-pdf-header-footer --print-to-pdf=.tmp/acceptance-browser.raw.pdf \
  specs/pdf-import-quality/fixtures/acceptance-source.html
```

LibreOffice 7.1 has no command-line switch for tagged export. Enable it in a
throwaway profile, then import the HTML with Writer:

```bash
mkdir -p .tmp/lo-profile/user
cat > .tmp/lo-profile/user/registrymodifications.xcu <<'XCU'
<?xml version="1.0" encoding="UTF-8"?>
<oor:items xmlns:oor="http://openoffice.org/2001/registry">
<item oor:path="/org.openoffice.Office.Common/Filter/PDF/Export"><prop oor:name="UseTaggedPDF" oor:op="fuse"><value>true</value></prop></item>
</oor:items>
XCU
soffice -env:UserInstallation=file://$PWD/.tmp/lo-profile --headless \
  "--infilter=HTML (StarWriter)" --convert-to pdf:writer_pdf_Export \
  --outdir .tmp specs/pdf-import-quality/fixtures/acceptance-source.html
```

Sanitize both raw exports with `producer-tools.ts sanitize-export ... --title
"Neutral Acceptance Handbook"`, then rerun `bun specs/pdf-import-quality/fixtures/update-manifest.ts`.
Word for Mac exports untagged PDFs without its online service, so there is no
tagged Word acceptance fixture.
